--- notes ---------------------------------------------------------------------------------

* A separate, shallower sweep on the same two binaries during development (n_kv 4,096 and
  8,192 with kv_type=1) gave 1.3223 -> 1.0613 ms and 2.4645 -> 1.9088 ms (-19.7% / -22.5%),
  with identical output md5 (1164c2763d5ddd39... / 083bf79a1fd73f01...).
* kv_type=1 (Q4_1 KV) in this harness aborts with "illegal memory access" at n_kv >= 16384,
  and its CPU reference reports a large bitdiff at any depth. The engine serves q4_1 at
  262,848 context without issue, so this is a harness allocation/reference bug: use
  kv_type=0 until it is fixed.
* Timings are wall-clock launch-loop minima on an idle GPU; both variants were run back to
  back in the same session, and the fixed binary was run twice at each shape with <2% spread.
